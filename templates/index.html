Token pool Contribute Copy push key Check dead tokens
Tokens are shared with the Cubey provider and persist across restarts/updates. Raw tokens are never exposed here -- only hashes. A token is evicted only after two consecutive dead probes. "Copy push key" is the credential the browser userscript (tools/jwt-uploader) uses to POST /api/jwt/push without a dashboard session; it is created on first click and stored in config/admin_config.json.

One bar per hour, last 72. Green is a request that answered, red is a 401/403 (the only kind that can kill a token), amber is anything else (rate limit, 5xx, timeout). The two hairlines under the chart are tokens entering the pool (blue) and leaving it (grey) — a bar with no blue hairline but a grey one is where the pool got thin.

App settings Reset defaults
Remote config for the tweak, served publicly at GET /api/app/settings (non-secret values only). These switches reach every device on every build. Devices re-check on foreground, at most once every 15 min.
Remote control
Targeted kill switch (by build)
The switches above reach every device on every build. This one targets a build sha, a tag, or a range of builds, so a bad build can be turned down without touching anyone else. The device sends the sha it was built with and the server resolves the selector, so nothing is evaluated on the device. A target that cannot be resolved is refused rather than stored — one that silently matched nothing would look armed while doing nothing.
